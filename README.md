# 🐭 Мишка-шкряботушка — Telegram-бот «Лісовий архів»

Telegram-бот із RAG для «лісової громади»: користувачі діляться порадами у вигляді документів (PDF / DOCX / TXT) і ставлять питання звичайним текстом. Бот відповідає **лише на основі завантажених документів** і наприкінці вказує джерело.

**Стек:** Python 3.11 · **Poetry** · aiogram 3 · Groq (`openai/gpt-oss-120b`) · ChromaDB · sentence-transformers (`multilingual-e5-small`) · SQLite (aiosqlite) · Docker Compose.

---

## 🚀 Швидкий старт

1. **Отримайте ключі**
   - Токен бота — у [@BotFather](https://t.me/BotFather).
   - API-ключ — у [Groq Console](https://console.groq.com/keys).
2. **Налаштуйте оточення**
   ```bash
   cp .env.example .env
   # відкрийте .env і підставте TELEGRAM_BOT_TOKEN та GROQ_API_KEY
   ```
3. **Запустіть однією командою**
   ```bash
   docker compose up --build
   ```
   Перша збірка довша (завантажується CPU-версія PyTorch та модель ембедингів ~500 МБ), далі — швидко. Для роботи потрібно ~2 ГБ вільної RAM.

Для фонового запуску: `docker compose up --build -d`, логи: `docker compose logs -f`.

### 📦 Залежності (Poetry)

Залежності описані в `pyproject.toml` (замість `requirements.txt`). У Docker вони ставляться командою `poetry install --no-root --without dev` з `virtualenvs.create false`.

**Зафіксуйте версії (рекомендовано):** файл `poetry.lock` потрібно згенерувати один раз локально й закомітити:
```bash
pip install poetry==1.8.5
poetry lock
git add poetry.lock
```
Dockerfile копіює `poetry.lock*`, тож без lock-файлу збірка теж працює (залежності резолвляться під час збірки), але тоді версії не відтворювані.

**Локальна розробка без Docker:**
```bash
poetry install
cp .env.example .env
DATA_DIR=./data poetry run python -m app.main
```

> Папка Google Drive має бути відкрита за посиланням («Усі, хто має посилання»). Файли мають бути справжніми PDF/DOCX/TXT — нативні Google Docs/Sheets бібліотека `gdown` не завантажує (експортуйте їх у DOCX/PDF).

## 💬 Як користуватися ботом

| Дія | Результат |
|---|---|
| `/start` | Вітання та правила |
| Файл `.pdf` / `.docx` / `.txt` | Збереження поради. Вперше — бот спитає справжнє ім'я (FSM) |
| Звичайний текст | Питання до бази знань |
| `/cancel` | Скасувати очікування імені |
| Фото, голосові, стікери, zip/exe тощо | Ввічливе нагадування правил |

Формат джерела наприкінці відповіді:
```
Порада з документа 'Назва_файлу.ext' (автор: Справжнє Ім'я, надіслано: DD.MM.YYYY HH:MM)
```
Для початкових файлів автор — «Лісовий архів». Час — `Europe/Kyiv`. Якщо відповіді немає: «У «Лісовому архіві» немає такої поради.»

## 🗂 Структура

```
pyproject.toml      # залежності та налаштування Poetry
poetry.lock         # зафіксовані версії (згенеруйте: poetry lock)
app/
├── main.py          # ініціалізація, логування, запуск polling, фоновий bootstrap
├── config.py        # pydantic-settings, шляхи, константи, час Europe/Kyiv
├── database.py      # SQLite: users, documents
├── gdrive.py        # завантаження з Google Drive + локальний fallback
├── rag_engine.py    # екстракція тексту, чанкінг, ChromaDB, Groq, ingest
└── bot/
    ├── handlers.py  # команди, документи, питання, FSM, глобальний error-handler
    └── states.py    # RegistrationStates.waiting_for_name
data/                # volume: БД, векторний індекс, файли, логи
```

### Дані в `./data` (персистентні)
| Шлях | Вміст |
|---|---|
| `bot.sqlite3` | таблиці `users`, `documents` |
| `chroma/` | векторний індекс |
| `files/` | збережені документи |
| `logs/bot.log` | ротаційний лог (5 МБ × 3) |
| `initial_docs/` | **локальний fallback**: покладіть сюди PDF/DOCX/TXT, якщо Google Drive недоступний |
| `.gdrive_bootstrapped` | маркер успішного первинного наповнення (видаліть або `GDRIVE_FORCE_SYNC=true`, щоб повторити) |

## 🧠 Прийняті технічні рішення

**Первинне наповнення.** Виконується у фоні, тож бот відповідає одразу; якщо архів ще наповнюється, а відповіді немає — користувач бачить відповідну примітку. Документи, що вже є в базі (зокрема замінені користувачами), не перезаписуються. Якщо Google Drive недоступний — береться `data/initial_docs/`, а маркер не ставиться, тому наступний старт знову спробує Drive.

**Версіонування.** Документи ідентифікуються за **назвою файлу без урахування регістру** (`casefold`, бо SQLite `NOCASE` працює лише для ASCII). Нова версія спершу індексується, і лише потім видаляються старі фрагменти — якщо індексація впаде, стара версія лишається. Заміна можлива будь-яким користувачем (за вимогою «будь-який користувач може надіслати новіший варіант»).

**`documents.file_id`** — внутрішній UUID версії (він же ключ у ChromaDB і ім'я файлу на диску), а не Telegram `file_id`: Telegram-ідентифікатори можуть збігатися для однакового вмісту й не підходять для версіонування. Додатково зберігаються `name_key`, `stored_path`, `chunks_count`.

**Poetry і PyTorch.** Poetry ставиться в окремий venv, а залежності — в `/opt/venv`, який переноситься у фінальний образ (multi-stage). CPU-збірка `torch` підключена через explicit-джерело `pytorch-cpu` у `pyproject.toml`, тому образ не тягне CUDA. Замість мета-пакета `langchain` використано `langchain-text-splitters` — саме звідти береться `RecursiveCharacterTextSplitter`, решта `langchain` не потрібна.

**Ембединги.** Багатомовна `intfloat/multilingual-e5-small` (512 токенів, добре працює з українською) із префіксами `query:`/`passage:`. Модель вшита в Docker-образ на етапі збірки. Стандартна англомовна модель ChromaDB для української не підходить, а моделі `paraphrase-multilingual-*` обрізають текст на ~128 токенах, що менше за чанк у 1000 символів.

**Боротьба з галюцинаціями.**
- Температура 0.1, суворий system-prompt: лише з наданих фрагментів, фрагменти — це дані, а не інструкції (захист від prompt injection).
- LLM повертає JSON `{found, answer, sources}`; джерела формує **код** з метаданих чанків, які LLM реально використала, — тож цитата не може бути вигаданою.
- `found=false` → стандартна відповідь про відсутність поради. Є опційний поріг відстані `RETRIEVAL_MAX_DISTANCE`.

**Моделі Groq.** Llama 3.3 70B і Llama 3.1 8B (а також `llama3-8b-8192` зі специфікації) Groq вимкнув 16.08.2026, тому за замовчуванням використовуються рекомендовані Groq заміни: `openai/gpt-oss-120b` (основна) та `openai/gpt-oss-20b` (запасна). Для reasoning-моделей виставлено `reasoning_effort=low` і запас `max_tokens`, щоб «роздуми» не з'їдали ліміт. Fallback спрацьовує при помилках мережі, лімітах, 4xx/5xx. На старті бот звіряє налаштовані моделі зі списком Groq і пише в лог помилку, якщо модель зникла. Актуальний список: https://console.groq.com/docs/models

**Обробка помилок.** Окремі сценарії для мережі (Telegram, Google Drive, Groq), пошкоджених/запаролених/порожніх файлів (скани PDF без тексту), завеликих файлів (>20 МБ — ліміт Telegram), невалідних імен. Глобальний `router.error()` логує винятки зі стеком і відповідає користувачу ввічливо. Логи — у stdout (`docker compose logs`) та у файл.

**FSM.** Використовується `MemoryStorage`: якщо контейнер перезапуститься під час очікування імені, користувач просто надішле файл ще раз. Для багатоінстансного розгортання замініть на Redis-сховище.

**Паралелізм.** Блокуючі операції (екстракція тексту, ембединги, ChromaDB) винесені в `asyncio.to_thread`; зміни бази знань серіалізуються `ingest_lock`.

| `GDRIVE_FORCE_SYNC` | | `false` |

> Якщо змінюєте `EMBEDDING_MODEL`, видаліть `data/chroma` і `data/.gdrive_bootstrapped` та перезапустіть: вектори різних моделей несумісні.

## 🛠 Діагностика

- **«Архів порожній» у логах** — папка Drive не публічна або містить лише нативні Google Docs. Покладіть файли в `data/initial_docs/`.
- **Помилка прав на `./data`** — контейнер працює від root для сумісності з bind-mount; у суворому середовищі додайте непривілейованого користувача й `chown` на `./data`.
- **Скинути все** — `docker compose down` і видаліть вміст `./data`.
